# CLAUDE.md

## Project

Rust port of [vlmcsd](https://github.com/Wind4/vlmcsd) (C KMS emulator). The C source lives at `/Users/mt/Coding/vlmcsd/src/` and is the reference for all protocol behavior.

## Architecture

Cargo workspace with 9 crates in `crates/`:

- **vlmcsd-types** — GUID, FileTime, Request/Response, wire serialization (manual LE byte parsing, no serde)
- **vlmcsd-crypto** — AES-128/160, SHA-256, HMAC-SHA256, AES-CMAC (all pure Rust, no external crypto crates)
- **vlmcsd-kmsdata** — KMD binary database parser, embeds `data/vlmcsd.kmd` via `include_bytes!`
- **vlmcsd-protocol** — KMS V4/V5/V6 protocol logic, ePID generation
- **vlmcsd-rpc** — DCE/RPC server-side (bind negotiation, NDR32/64, request dispatch)
- **vlmcsd-network** — TCP listener, thread-per-connection, graceful shutdown via `AtomicBool`
- **vlmcsd-server** — `vlmcsd` binary (daemon mode, signal handling, PID file)
- **vlmcsd-client** — `vlmcs` binary (RPC client bind, V4/V5/V6 request/response)
- **vlmcsd-ffi** — C FFI library (cdylib + staticlib), header generated by cbindgen

## Design rules

- No external crypto dependencies — AES, SHA-256, HMAC are ported from the C source
- No tokio, no serde, no async — `std::thread` per connection
- No `repr(C, packed)` — all wire parsing is manual from `&[u8]` with explicit LE byte order
- Minimal dependencies: only `libc` (Unix signal handling) and `cbindgen` (build-time FFI header)
- When in doubt about protocol behavior, read the C source — it is authoritative

## Building and testing

```sh
cargo build --release    # binaries at target/release/vlmcsd and target/release/vlmcs
cargo test               # 38 tests including integration tests (starts real TCP servers)
```

Integration tests in `crates/vlmcsd-network/tests/integration.rs` bind to ports 31688-31690 — ensure those are free.

## CI

GitHub Actions workflow at `.github/workflows/build.yml` builds 8 targets. Pushing a `v*` tag creates a GitHub Release with binaries. Check CI before tagging: `gh run list`.

## Key gotchas

- AES key schedule: the `sub_dword` function uses `to_ne_bytes()`/`from_ne_bytes()` to match C's memory-order byte manipulation. This was a subtle porting bug — do not change to `to_be_bytes()`.
- V6 HMAC uses a time-slot mechanism with constants `TIME_C1`/`TIME_C2`/`TIME_C3` — the slot calculation must match the C implementation exactly.
- The non-blocking listener for graceful shutdown means accepted sockets inherit non-blocking mode — `handle_client` relies on `set_nonblocking(false)` being called immediately after accept.
- `create_request_v6` encrypts with CBC using a random IV prepended to the ciphertext. The server decrypts starting from offset 4 (after the version field) with no explicit IV (uses zeros).
